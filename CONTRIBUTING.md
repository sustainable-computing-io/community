# Contributing to repositories in the sustainable-computing-io org, such as Kepler ⚡

Thanks for your interest in contributing to Kepler! This guide covers what applies across all repositories in this GitHub organization. Each repository's `CONTRIBUTING.md` covers its development setup, tests, and CI.

| Repository | What it holds |
| --- | --- |
| [kepler](https://github.com/sustainable-computing-io/kepler) | Kepler exporter |
| [kepler-operator](https://github.com/sustainable-computing-io/kepler-operator) | Kubernetes operator for Kepler |
| [kepler-doc](https://github.com/sustainable-computing-io/kepler-doc) | Documentation website |
| [community](https://github.com/sustainable-computing-io/community) | Community meetings and shared contribution guidelines |

## Ways to Contribute 💡

Code, documentation, bug reports, feature ideas, PR reviews, and tests all count. Even fixing a typo helps!

## Before You Start 🤔

- Search the repository's issues to avoid duplicates.
- For new features or design changes, open an issue first, then submit a PR.
- New to Kepler? Look for issues labeled `good first issue` or `help wanted`, and ask questions in [#kepler-project](https://cloud-native.slack.com/archives/C05QK3KN3HT) on the [CNCF Slack](https://slack.cncf.io).

## Reporting Bugs 🐛

Open an issue with the bug template and include:

- Steps to reproduce
- Expected and actual behavior
- Logs or screenshots
- Environment details (OS, Kubernetes version, Kepler version)

## Suggesting Enhancements ✨

Open an issue with the enhancement template and explain:

- What you propose
- Why it helps most Kepler users
- Any implementation ideas

## Pull Requests 🚀

1. Fork the repository and create a branch.
2. Make your changes and follow the repository's development guide.
3. Sign off every commit with `git commit -s` to meet the [DCO](https://developercertificate.org/) requirement.
4. Open a pull request and make sure CI passes.
5. Address maintainer feedback. A maintainer merges the PR once approved.

Keep each commit a coherent change with a meaningful message, and fold review follow-ups into the commits they belong to. Each repository enforces its own commit message format.

## Keep Your Company Affiliation Up to Date 🏢

The CNCF tracks project health on [Kepler DevStats](https://kepler.devstats.cncf.io/d/5/companies-table?orgId=1) using affiliation data from [cncf/gitdm](https://github.com/cncf/gitdm). Contributors without a `cncf/gitdm` entry count toward no company.

If you work for a company, university, or research institution, add or update your affiliation in [cncf/gitdm](https://github.com/cncf/gitdm) following its README.
